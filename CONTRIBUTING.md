# Contributing

Changes must preserve the distinction between an executable observation, an ideal one-time-mask assumption, a computational browser implementation, and a security claim.

Before submitting a change:

1. Read `README.md`, `SECURITY.md`, and `docs/a-d-04-brief.md`.
2. Cite primary cryptographic sources for changes to the construction, observer model, or attacks.
3. Keep the key-sharing graph separate from transport topology and keep omniscient simulator state out of observer objects.
4. Add negative tests for malformed, dishonest, missing, reused, and disclosed-key behavior, not only an honest round.
5. Independently recompute learner-visible values rather than testing application labels against themselves.
6. Preserve keyboard access, live-region behavior, dark-theme contrast, reduced-motion behavior, and phone reflow.
7. Do not weaken coverage, mutation, accessibility, dependency-audit, CodeQL, or deployment gates to make CI green.
8. Run every command in the README verification block. Run the mutation command only from a clean committed tree, as the runner requires.

Never commit real messages, identities, shared secrets, credentials, tokens, personal data, or production endpoints. All lesson participants and protocol evidence must remain synthetic.
